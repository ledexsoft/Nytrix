Nytrix Enterprise e pensato per organizzazioni che vogliono assicurarsi che codice e dati non escano mai dalla propria infrastruttura. Questo e possibile grazie a una config centralizzata che si integra con SSO e con il gateway AI interno.

:::

## Prova

Nytrix e open source e non memorizza alcun tuo codice o dato di contesto, quindi i tuoi sviluppatori possono semplicemente [iniziare](/docs/) e fare una prova.

---

### Gestione dati

**Nytrix non memorizza il tuo codice o i tuoi dati di contesto.** Tutta l'elaborazione avviene in locale o tramite chiamate API dirette al tuo provider AI.

Questo significa che, finche usi un provider di cui ti fidi o un gateway AI interno, puoi usare Nytrix in modo sicuro.

---

### Proprietà del codice

**Sei proprietario di tutto il codice prodotto da Nytrix.** Non ci sono restrizioni di licenza o rivendicazioni di proprieta.

---

## Prezzi

Usiamo un modello per-seat per Nytrix Enterprise. Se hai un tuo gateway LLM, non addebitiamo i token usati. Per maggiori dettagli su prezzi e opzioni di implementazione, **<a href={enterprise}>contattaci</a>**.

## Distribuzione

Quando hai completato la prova e sei pronto a usare Nytrix nella tua organizzazione, puoi **<a href={enterprise}>contattarci</a>** per discutere prezzi e opzioni di implementazione.

---

### Configurazione centralizzata

Possiamo configurare Nytrix per usare un'unica config centralizzata per tutta l'organizzazione.

Questa config centralizzata puo integrarsi col provider SSO e garantisce che tutti gli utenti accedano solo al gateway AI interno.

---

### Integrazione SSO

Tramite la config centralizzata, Nytrix puo integrarsi col provider SSO della tua organizzazione per l'autenticazione.

Questo consente a Nytrix di ottenere credenziali per il gateway AI interno tramite il sistema di identity management esistente.

---

### Gateway AI interno

Con la config centralizzata, Nytrix puo anche essere configurato per usare solo il tuo gateway AI interno.

Puoi anche disabilitare tutti gli altri provider AI, assicurandoti che tutte le richieste passino dall'infrastruttura approvata dalla tua organizzazione.

---

### Hosting autonomo

Anche se consigliamo di disabilitare le pagine di condivisione per assicurarti che i dati non escano mai dall'organizzazione, possiamo anche aiutarti a ospitarle sulla tua infrastruttura.

Questa funzionalita e nella nostra roadmap. Se ti interessa, **<a href={enterprise}>faccelo sapere</a>**.

<details>
<summary>Possiamo usare un registry NPM privato?</summary>

Nytrix supporta registry npm privati tramite il supporto nativo di Bun per i file `.npmrc`. Se la tua organizzazione usa un registry privato, come JFrog Artifactory, Nexus o simili, assicurati che gli sviluppatori siano autenticati prima di eseguire Nytrix.

Per configurare l'autenticazione col registry privato:

```bash
npm login --registry=https://your-company.jfrog.io/api/npm/npm-virtual/
```

Questo crea `~/.npmrc` con i dettagli di autenticazione. Nytrix lo rilevera automaticamente.

:::caution
Devi essere autenticato nel registry privato prima di eseguire Nytrix.
:::

In alternativa, puoi configurare manualmente un file `.npmrc`:

```bash title="~/.npmrc"
registry=https://your-company.jfrog.io/api/npm/npm-virtual/
//your-company.jfrog.io/api/npm/npm-virtual/:_authToken=${NPM_AUTH_TOKEN}
```

Gli sviluppatori devono essere autenticati nel registry privato prima di eseguire Nytrix per garantire che i pacchetti possano essere installati dal registry enterprise.

</details>
